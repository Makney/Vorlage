# Roadmap – Übersicht

Das Projekt ist in **3 Phasen** aufgeteilt, jede mündet in einem Versions-Milestone.

Features haben **keine feste Reihenfolge** – jede Implementierung findet in einer eigenen Season statt. Ausnahme: Features, die aufeinander aufbauen, sind innerhalb ihrer Phase in **Feature-Blöcken** gebündelt (Reihenfolge innerhalb des Blocks muss eingehalten werden, alles andere ist frei wählbar).

| Phase                              | Ziel                                          | Milestone | Status |
| ---------------------------------- | --------------------------------------------- | --------- | ------ |
| [Phase 1](./ROADMAP_PHASE1.md)     | Minimal lauffähige Version                    | v0.1      | ⛔      |
| [Phase 2](./ROADMAP_PHASE2.md)     | Intelligente Erweiterungen                    | v1.0      | ⛔      |
| [Phase 3](./ROADMAP_PHASE3.md)     | Aufwändige Zusatzfunktionen                   | —         | ⛔      |

Abgeschlossene Features → [CHANGELOG.md](./CHANGELOG.md)

## Was NICHT geplant ist

Hier kommt die **Negativ-Liste** rein — Dinge, die ein Nutzer vielleicht erwartet, die aber bewusst *nicht* Teil dieses Projekts sind. Schafft Scope-Klarheit für zukünftige Feature-Vorschläge.

- *(Platzhalter — pro Projekt ausfüllen, z.B. „Kein Multi-User", „Kein Cloud-Sync", „Keine Bezahl-Features")*
