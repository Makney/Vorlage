# Glossary

Domain-specific terms, abbreviations, and project-internal concepts. Read this file when an unfamiliar term appears in a user prompt or when planning a feature whose domain is unclear.

## When to add an entry

- A term has a project-specific meaning that differs from common usage.
- An abbreviation is used that is not universally known.
- A domain concept cannot be inferred from code or docs alone.

**Not here:** general programming terms, framework concepts covered by official docs.

---

## Project-Internal Terms

### Season

A single focused development session with one clearly scoped feature goal. Corresponds to one invocation of `templates/SEASON_PROMPT.md`. Tracked retrospectively in `SEASON_LOG.md` and by result in `CHANGELOG.md`.

### Phase

A group of seasons leading to a version milestone (v0.1, v1.0, …). Three phases are defined in `roadmap/ROADMAP.md`; details per phase in `roadmap/PHASE<N>.md`.
